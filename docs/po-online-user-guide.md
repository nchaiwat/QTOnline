# คู่มือผู้ใช้ระบบ PO-Online

> เวอร์ชันเอกสาร: 1.0  
> อัปเดตล่าสุด: 16 พฤศจิกายน 2025  
> จุดประสงค์: เอกสารฉบับนี้ใช้เป็นแม่แบบสำหรับสร้างคู่มือ PDF ที่มีภาพหน้าจอประกอบ โดยครอบคลุมขั้นตอนการใช้งานพื้นฐานของผู้ใช้แต่ละบทบาท (Sale, Sale Admin, Administrator)

---

## 1. ภาพรวมระบบ
- **ชื่อระบบ:** PO-Online (Purchase Order Online)
- **เทคโนโลยีหลัก:** Flask (Backend), HTML/CSS/JavaScript (Frontend), PostgreSQL (ฐานข้อมูล)
- **คุณสมบัติหลัก:**
  - จัดการใบสั่งซื้อ (สร้าง, ส่งอนุมัติ, อนุมัติ, ขอแก้ไข, อัปโหลดเอกสารลงนาม)
  - จัดการข้อมูลลูกค้าและสินค้า (นำเข้า CSV, ค้นหา, แก้ไข, ลบ)
  - แสดงสถิติภาพรวมบนแดชบอร์ด
  - จัดการบัญชีผู้ใช้ (เฉพาะ Administrator)

### 1.1 บทบาทผู้ใช้
| บทบาท | ความสามารถหลัก |
|--------|-----------------|
| **Sale** | สร้าง/แก้ไข PO ของตนเอง, ส่งรีวิว, ตอบคำขอแก้ไข, อัปโหลด Signed PO |
| **Sale Admin** | ตรวจสอบและอนุมัติ PO, ขอแก้ไข, จัดการลูกค้า/สินค้า, ส่งออกข้อมูล |
| **Administrator** | มีสิทธิ์ทุกอย่าง รวมถึงจัดการผู้ใช้ |

---

## 2. โครงสร้างหน้าเว็บหลัก
1. **Login Page** – หน้าลงชื่อเข้าใช้ระบบ
2. **Dashboard** – สรุปสถิติ PO ตามสถานะ
3. **PO Management** – รายการ PO พร้อมตัวกรองและการค้นหา
4. **PO Detail** – รายละเอียด PO, คอมเมนต์, ปุ่มดำเนินการตามสถานะ/บทบาท
5. **Create/Edit PO** – แบบฟอร์มสร้างหรือแก้ไข PO
6. **Customer Management** – รายการลูกค้า, อัปโหลด CSV, ดูรายละเอียด
7. **Product Management** – รายการสินค้า, อัปโหลด CSV, ดูรายละเอียด
8. **User Management** – เฉพาะ Administrator สำหรับจัดการบัญชีผู้ใช้

> **พื้นที่สำหรับภาพหน้าจอ**: แนะนำให้เว้นพื้นที่/ตารางเพื่อแทรกรูปขณะจับภาพ เช่น

## 3. ขั้นตอนการทำงาน (Workflow)

### 3.1 กระบวนการสร้างและอนุมัติ PO
1. **Sale**: เข้าสู่ระบบ → เลือกเมนู `PO Management` → คลิก `Create New PO`
2. เลือลูกค้าจากโมดัลค้นหา → ระบุวันส่งสินค้า → เพิ่มสินค้า (เลือกสินค้า, ใส่จำนวน, ส่วนลด)
3. `Save Draft` (บันทึกร่าง) หรือ `Submit for Review` (ส่งขออนุมัติ)
4. **Sale Admin / Administrator**: เปิด PO สถานะ `Pending Review` → ตรวจสอบรายละเอียด → `Approve PO` หรือ `Request Changes` พร้อมคอมเมนต์
5. **Sale**: หากถูกขอแก้ไข → แก้ไขข้อมูลตามคำแนะนำ → `Submit for Review` อีกครั้ง
6. เมื่ออนุมัติ → สถานะเป็น `Approved` → Sale อัปโหลด `Signed PO` (PDF) → สถานะอาจเปลี่ยนเป็น `Completed`

> **พื้นที่สำหรับภาพหน้าจอ**: ใส่ภาพประกอบแต่ละขั้นตอน เช่น การเลือกสินค้า, ปุ่มอนุมัติ, ฟอร์มคอมเมนต์

### 3.2 การจัดการลูกค้าและสินค้า (เฉพาะ Sale Admin/Administrator)
1. ไปที่เมนู `Customers` หรือ `Products`
2. ใช้ปุ่ม `Download Template` เพื่อดาวน์โหลดไฟล์ CSV ตัวอย่าง
3. จัดเตรียมไฟล์ข้อมูล → คลิก `Upload File` เพื่ออัปโหลดเข้าสู่ระบบ
4. ใช้การค้นหา/กรองเพื่อตรวจสอบข้อมูลที่นำเข้า

### 3.3 การจัดการผู้ใช้ (Administrator)
1. เข้าเมนู `User Management`
2. `Create User` เพื่อเพิ่มบัญชีใหม่ (ระบุ username, full name, role, password)
3. เลือกผู้ใช้ในตารางเพื่อแก้ไข/ลบตามสิทธิ์ที่กำหนด

## 4. คู่มือการใช้งานตามบทบาท

### 4.1 ผู้ใช้ Sale
- **เข้าระบบ**: กรอก username/password บนหน้า Login
- **สร้างใบสั่งซื้อ**: ดูขั้นตอนในหัวข้อ 3.1
- **ค้นหารายการของตน**: ใช้ช่อง `Search` หรือ `Status` filter ในหน้า PO Management
- **อัปโหลดเอกสารลงนาม**: หลัง PO ได้รับอนุมัติ → เปิด PO Detail → ปุ่ม `Upload Signed PO`
- **ลบ PO**: ทำได้เฉพาะสถานะ Draft ของตัวเอง → `Delete Draft`

### 4.2 ผู้ใช้ Sale Admin
- **ตรวจสอบ/อนุมัติ PO**: เปิด PO Pending Review → ปุ่ม `Approve PO`
- **ขอแก้ไข**: กรอกคอมเมนต์ → `Request Changes`
- **จัดการข้อมูลลูกค้า/สินค้า**: ใช้ฟังก์ชันนำเข้า CSV, ลบข้อมูลที่ไม่ต้องการ
- **ส่งออกข้อมูล**: ปุ่ม `Export PDF/Excel` ในหน้า PO Management

### 4.3 ผู้ใช้ Administrator
- **สิทธิ์ทั้งหมดของ Sale Admin**
- **จัดการผู้ใช้**: ดูหัวข้อ 3.3 เพื่อเพิ่ม/แก้ไข/ลบผู้ใช้
- **การตรวจสอบเชิงลึก**: สามารถดูรายละเอียดทุกหน้ารวมถึง PO ที่ไม่ใช่ของตน (ยกเว้น Draft ของผู้อื่น)

## 5. คำแนะนำในการจับภาพหน้าจอสำหรับคู่มือ PDF

1. **เตรียมสภาพแวดล้อม**
   - ใช้ข้อมูลจริงหรือข้อมูลตัวอย่างที่ครบถ้วน (ลูกค้า, สินค้า, PO) เพื่อให้ภาพสื่อสารชัดเจน
   - ปรับหน้าจอเป็นโหมด Full HD (1920×1080) หรือความละเอียดสูงกว่า เพื่อความคมชัดในการพิมพ์

2. **จับภาพหน้าจอ**
   - Windows: ใช้ `Snipping Tool`, `Snip & Sketch`, หรือ `Win + Shift + S`
   - Mac: ใช้ `Cmd + Shift + 4` (เลือกพื้นที่)
   - จัดเก็บไฟล์เป็น `.png` หรือ `.jpg` ในโฟลเดอร์ `docs/screenshots/`
   - ตั้งชื่อไฟล์ให้มีความหมาย เช่น `dashboard-overview.png`, `po-detail-approve.png`

3. **ใส่หมายเลข/คำอธิบาย**
   - ใช้แอปแก้ไขภาพ (เช่น PowerPoint, Figma, Snagit) เพิ่มหมายเลขหรือกรอบ highlight ในส่วนสำคัญ
   - เพิ่มคำบรรยายสั้น ๆ ใต้ภาพในเอกสาร (อธิบายว่าภาพนี้แสดงอะไร)

4. **อัปเดตเอกสาร Markdown/Word**
   - ใน Markdown ใช้ไวยากรณ์ `![คำอธิบาย](../screenshots/ไฟล์ภาพ.png)`
   - หากใช้ Word/Google Docs ให้แทรกภาพแล้วจัด layout ตามต้องการ

5. **สร้างไฟล์ PDF**
   - หากร่างใน Markdown: ใช้เครื่องมือแปลง เช่น `pandoc`, `typora`, หรือเครื่องมือออนไลน์แปลง Markdown → PDF
   - หากใช้ Word/Google Docs: ใช้คำสั่ง `Save as PDF` หรือ `Download as PDF`
   - ตรวจสอบว่าไฟล์ PDF มีสารบัญ (หากต้องการ) และภาพคมชัด

6. **ตรวจทานและเผยแพร่**
   - ตรวจคำสะกด/รูปแบบก่อนเผยแพร่
   - เก็บไฟล์ต้นฉบับ (.md หรือ .docx) พร้อม PDF ในที่เดียวกัน (เช่น `docs/`)
   - หากต้องส่งให้ทีมอื่นตรวจ สามารถใช้ลิงก์หรือแนบไฟล์ PDF ผ่านอีเมล/ระบบจัดเก็บเอกสาร (SharePoint, Google Drive)
